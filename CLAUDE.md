# CLAUDE.md

This file provides guidance to Claude Code (and similar coding agents) when working in this repository.

## Project Overview

`raytracer` is a C++ raytracing library focused on speed and interactive rendering. It splits image rendering across multiple threads to render parts of an image in parallel and ships several runnable examples (including an interactive `SceneBrowser`) plus a CLI rendering tool. The library is templatized and built around pluggable cameras, materials, shapes, samplers, and view planes.

## Tech Stack

- C++17 (`g++`)
- Qt 5 (`QtCore`, `QtGui`, `QtWidgets`, `QtScript`) for widgets and example apps
- Rake (Ruby) as the build driver — there is no CMake or Make file
- Google Test + Google Mock (vendored under `gtest/` and `gmock/`)
- Doxygen for API docs
- `cppcheck` for static analysis
- `lcov` / `genhtml` for coverage reports
- SSE3 optimizations on supported targets

## Repository Structure

- `include/` — public headers, grouped by module
  - `core/` — `Color`, `Buffer`, math (`Vector`, `Ray`, `Rect`), geometry, formats, util
  - `raytracer/` — `Raytracer`, `State`, plus `cameras/`, `primitives/`, `materials/`, `lights/`, `samplers/`, `textures/`, `viewplanes/`, `brdf/`
  - `world/` — scene/world abstractions
  - `widgets/` — Qt widget headers
- `src/` — implementations mirroring the `include/` layout
- `test/` — `unit/`, `functional/`, `helpers/`, `mocks/`, `abstract/`, `fixtures/`, `coverage/`
- `examples/` — `SceneBrowser`, `DifferenceRayTracer`, `GeneratedRayTracer`, `RefractingRayTracer`
- `tools/rendercli/` — command-line renderer
- `scripts/` — Ruby/JS helpers, including `render_docs.rb` and scene scripts
- `gtest/`, `gmock/` — vendored test frameworks
- `Rakefile`, `Doxyfile`, `.cppchecksuppress` — top-level config

## Common Commands

Build everything (examples + tools + tests):

    rake

Build only examples or only tools:

    rake examples
    rake tools

Run all tests (build + run):

    rake test

Run just unit or functional tests; filter with `ONLY`:

    rake test:units
    rake test:functionals
    ONLY=PinholeCamera.* rake test:units

Static analysis and inline-method check:

    rake check:cpp
    rake check:inline

Generate documentation (Doxygen + rendered example images):

    rake docs

Coverage report (writes `test/coverage/`):

    rake test:coverage

Code/test line stats:

    rake stats

Debug build (adds `-g -fno-inline -fsanitize=address`):

    DEBUG=1 rake

## Architecture & Conventions

- Headers live under `include/<module>/` and implementations under the matching `src/<module>/` path. Tests under `test/unit/<module>/` and `test/functional/` mirror the same tree.
- Public headers use `#pragma once` and forward-declare collaborators where possible (see `include/raytracer/Raytracer.h`).
- The library leans on templates (e.g. `Vector<T>`, `Buffer<T>`, `Colord`) and pluggable strategies — cameras, materials, primitives, samplers, and view planes are all interface-driven.
- `Raytracer` owns a `Camera` (via `std::shared_ptr`) and a non-owning `Scene*`, exposes `render(Buffer<unsigned int>&)`, supports cancellation, and uses a pimpl (`struct Private`) to hide threading details.
- Qt `moc`/`uic` outputs are generated by Rake rules from `.h`/`.ui` files into `.moc`/`.uic` siblings; do not edit those generated files.
- Compiler flags: `-std=c++17 -O3 -funroll-loops -mtune=native -W -Wall -pedantic -Wno-extra-semi`. `COVERAGE=1` switches to `-O1` plus `-fprofile-arcs -ftest-coverage`.
- `cppcheck` suppressions are tracked in `.cppchecksuppress`.

## Testing

- Framework: Google Test (with Google Mock), vendored in-tree.
- Test files are named `*Test.cpp` and the Rakefile keys off that suffix to apply test-specific compile flags.
- Two suites: `test/unit/` and `test/functional/`, each producing a `tests.run` binary.
- Run everything with `rake test`, or target a suite with `rake test:units` / `rake test:functionals`. Filter individual tests via `ONLY=` (passed through as `--gtest_filter`).
- Helpers, mocks, abstract base tests, and fixtures live alongside the suites under `test/`.

## Notes / Gotchas

- `Rakefile` hard-codes a macOS Homebrew Qt path (`QT_BASE = '/opt/homebrew/Cellar/qt@5/5.15.8_1'`). On other systems you must edit these constants before `rake` will succeed.
- Tests are launched with `DYLD_FRAMEWORK_PATH` set to the Qt lib dir, which is macOS-specific; Linux users will need an equivalent (`LD_LIBRARY_PATH`) tweak.
- The Rakefile computes header dependencies by scanning `#include "..."` directives itself rather than using compiler-generated `.d` files; if includes change in unexpected ways, a `rake clean` may be required.
- `rake test:coverage` shells out to `drake -j 24` for the parallel build step — install `drake` (the Ruby parallel rake) or substitute `rake -j` if unavailable.
- The most useful example to launch interactively is `examples/SceneBrowser/SceneBrowser`.
