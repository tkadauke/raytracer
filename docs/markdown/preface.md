# Preface

This is a long-form companion to the
[`tkadauke/raytracer`](https://github.com/tkadauke/raytracer) codebase.
The Doxygen-generated reference (under
[`docs/html/`](../html/)) tells you what every class does. This book
tells you *why*: how the pieces fit, what problem each one solves, and
how the math behind it works.

## What you'll find here

- **Narrative chapters** that explain a concept end-to-end —
  motivation, math, algorithm, code, variants. Each chapter declares
  the source files it's "about" and links back to them at every
  appropriate point.
- **Code excerpts**. Three to ten lines at a time, with a fenced
  `// path/to/file.h:line` caption and a link to the file on GitHub.
  Whole-class listings are the wrong unit — the link does that
  better.
- **Rendered images** generated by the project's own engines, used
  to show what a parameter does to the visible output (pinhole vs
  orthographic, low spp vs high spp, tonemap variants).
- **Small interactive figures** at the points where a static image
  cannot show a continuous parameter or an algorithm running step
  by step. They are illustrations of the surrounding prose, not a
  destination.

## What you won't find here

- A research survey. We cite foundational papers (Whitted 1980, Pineda
  1988, Möller-Trumbore 1997, MacDonald & Booth 1990,
  Heckbert-Moreton 1991, Narkowicz 2015 ACES, etc.) but the
  explanations are written for a programmer who wants to build, not a
  researcher who wants to compare.
- Topics not yet in the codebase. Path tracing, ReSTIR, photogrammetry,
  NeRF/3DGS, color science beyond tonemap operators, shadow algorithms
  beyond hard point-source shadows — all queued in
  [`docs/topics-backlog.md`](../topics-backlog.md), none documented
  here until they ship.
- A Doxygen replacement. The per-class `@brief` / `@param` blocks are
  the API reference. The book is the *narrative*.

## Who this is for

Computer-graphics-curious software engineers. The book assumes:

- C++ comfort (classes, templates, STL, smart pointers).
- High-school + first-year-undergrad math (vectors, dot/cross
  products, basic trigonometry, solving quadratics).
- No prior graphics knowledge beyond "a pixel is a colored square."

Things explained inline as needed: barycentric coordinates,
homogeneous coordinates, Snell's law, BRDFs, signed distance, the
rendering equation (briefly). Things linked but not derived: the
calculus and probability behind Monte Carlo sampling — those land
when path tracing does.

## How to read it

The [README](README.md) lists three reading paths. The default is
top-to-bottom; the alternatives let you skip directly to the
raytracer, the rasterizer, or a specific source file.

Conventions for cross-linking, code references, math notation, widget
embedding, and image embedding are documented in
[`docs/plans/complete/textbook.md`](../plans/complete/textbook.md) §3 — useful if you're
*writing* a chapter, not just reading one.

## A note on staleness

A textbook that lags the codebase is worse than no textbook at all.
The project keeps the two aligned through:

- A [`CLAUDE.md`](../../CLAUDE.md) rule: PRs that move, rename, or
  delete files appearing in a chapter's *Source anchors* list update
  the chapter in the same PR. Same for new public behaviour and new /
  removed widgets.
- A `rake docs:textbook:check` task that fails CI if any local link target,
  widget reference, source anchor, chapter order, or chapter reachability goes
  stale.
- A generated source-map appendix, refreshed with
  `rake docs:textbook:source-map`, that keeps chapter/source relationships
  visible.

If you find a stale reference, please open an issue or a PR. Drift is
a bug.
