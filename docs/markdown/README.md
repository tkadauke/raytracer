# Building a renderer, with the source open

> A long-form, wiki-style companion to the
> [`tkadauke/raytracer`](https://github.com/tkadauke/raytracer)
> codebase. Reads top-to-bottom as a textbook; navigates sideways
> as a wiki.

This book exists because a renderer is most interesting when you
can read the code that produces each pixel. Every chapter pairs
the math with the implementation and links to the exact file in
the codebase the prose is talking about. Where it helps the
narrative, the chapter also embeds a small interactive figure or
a rendered image; those are illustrations, not the point.

It documents what the codebase actually contains. Topics queued in
[`docs/topics-backlog.md`](../topics-backlog.md) — path tracing, ReSTIR,
photogrammetry, NeRF/3DGS, and more — get chapters when they ship,
not before.

The plan that produced this structure is at
[`docs/plans/complete/textbook.md`](../plans/complete/textbook.md). Conventions for
cross-linking, code references, math notation, widget embedding, and
image embedding are documented there too.

## Reading paths

### Top-to-bottom

Volumes I → II → III → IV → V → VI → VII → VIII, in order. The longest path;
works if you have time and want the full picture.

### "I just want to understand the raytracer"

Volume I, then Volume II in full, then chapters 13–16 from Volume III.
Skip rasterization and CV. About 16 chapters.

### "I just want to understand the rasterizer"

Volume I, then chapter 5 (the Whitted overview, for the engine
abstraction), then Volume IV in full, then chapter 17 from Volume IV
revisits Volume I's geometry primitives. About 10 chapters.

### "I want to fix one specific thing"

Use [Appendix C — Source map](appendix/c-source-map.md). It indexes
every header against the chapters that reference it.

### "I want to understand animation"

Read chapter 16 for the renderer's existing velocity-based motion blur, then
chapter 28 for frame timelines and keyframe interpolation.

## Conventions in one paragraph

Headings carry stable anchor IDs (`<a id="...">`) so inbound links
survive a rename. Code references use a fenced block with a
`// path/to/file.h:line` caption and a relative link to the file.
Math is KaTeX (`$inline$` and `$$display$$`). Widgets embed via a
`<!-- widget: name -->` source marker that the publish flow expands
into a runnable iframe. Rendered images embed as standard
`![alt](../../docs/images/foo.png)`. Each chapter ends with a
**See also** section.

For the full conventions, see
[`docs/plans/complete/textbook.md`](../plans/complete/textbook.md) §3.
