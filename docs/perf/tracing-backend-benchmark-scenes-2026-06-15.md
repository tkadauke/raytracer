# Tracing Backend Benchmark Scenes - 2026-06-15

Epic #566 needs repeatable scenes before CPU, hybrid, GPU, and fallback
thresholds can become automatic policy. This suite defines the scene categories
used by the wavefront intersection backend microbenchmarks and by rendercli
captures.

## Commands

Build rendercli and the benchmark binary:

```sh
cmake --preset release
cmake --build --preset release --target rendercli
cmake --preset benchmark
cmake --build --preset benchmark --target benchmarks
```

List the C++ microbenchmark rows:

```sh
./build/benchmark/benchmarks/benchmarks \
  --benchmark_filter=WavefrontIntersection --benchmark_list_tests=true
```

Capture one rendercli benchmark scene:

```sh
benchmarks/tracing_backend_capture.sh small_primitive
benchmarks/tracing_backend_capture.sh large_mesh
benchmarks/tracing_backend_capture.sh visibility_heavy
benchmarks/tracing_backend_capture.sh indirect_diffuse
benchmarks/tracing_backend_capture.sh unsupported_fallback
```

Capture the full rendercli set:

```sh
benchmarks/tracing_backend_capture.sh all
```

Outputs default to `tmp/tracing-backend-benchmarks/<scene>/`. Override the
rendercli path or output directory with `RENDERCLI=/path/to/rendercli` and
`TRACING_BACKEND_OUT=/path/to/output`. The wrapper also accepts
`TRACING_BACKEND_WIDTH`, `TRACING_BACKEND_HEIGHT`, `TRACING_BACKEND_REPEAT`,
`TRACING_BACKEND_SAMPLES`, `TRACING_BACKEND_DEPTH`, and
`TRACING_BACKEND_LARGE_MESH_SIDE`.

## Scene Set

| Scene | Rendercli source | Benchmark source | Backend purpose |
| --- | --- | --- | --- |
| `small_primitive` | `test/fixtures/tracing_parity/matte_direct_light.json` | `small_supported` | Low-overhead supported analytic scene for CPU and auto-selection floor checks. |
| `large_mesh` | Generated by `benchmarks/tracing_backend_capture.sh` | `mesh_heavy_supported` | Supported triangle-heavy scene for upload cost, BVH traversal, and GPU amortization checks. |
| `visibility_heavy` | `test/fixtures/tracing_parity/visibility_heavy.json` | `visibility_heavy_supported` | Area-light/direct-light scene that stresses any-hit visibility batches. |
| `indirect_diffuse` | `test/fixtures/tracing_parity/indirect_bounce.json` | `indirect_diffuse_supported` | Multi-depth diffuse path-tracing scene that exercises closest-hit and direct-light visibility work. |
| `unsupported_fallback` | `test/fixtures/tracing_parity/transparent_fallback.json` | `unsupported_mixed` | Explicit fallback workload; GPU requests must report runtime CPU fallback instead of silently claiming GPU execution. |

`benchmarks/scenes/tracing_backend_benchmark_scenes.json` repeats the same set
in machine-readable form. The rendercli wrapper uses project-owned fixture
scenes where possible and generates the large mesh deterministically so the
checked-in tree does not carry hundreds of repetitive triangle objects.

## Coverage

The supported rendercli scenes run in three modes:

- `--wavefront_intersection_backend cpu`, the CPU reference path;
- `--wavefront_intersection_backend auto`, the conservative automatic policy;
- `--wavefront_intersection_backend gpu`, the explicit platform request, which
  may resolve to Metal, Vulkan, packed CPU, or runtime CPU with a fallback
  reason.

The unsupported fallback scene runs only the explicit GPU request. That keeps
the fallback benchmark focused on the observable behavior that matters:
`intersectionBackendRequest` remains `gpu`, while the selected backend,
availability, execution path, compiled-scene unsupported counts, and fallback
reason describe why CPU execution was used.

The Google Benchmark suite covers the same categories through
`benchmarks/WavefrontIntersectionBackendBenchmark.cpp`. It reports compile and
pack cost, runtime CPU closest-hit/any-hit rows, packed closest-hit/any-hit
rows, automatic backend rows, `IntersectionService` rows, mixed query-family
rows, explicit GPU rows when the platform backend is enabled, and the
unsupported GPU fallback row.

## Initial Use

This document defines the benchmark scenes only. It intentionally does not set
pass/fail thresholds or choose automatic GPU policy cutoffs. Those belong to
the follow-up metric-capture and policy jobs after the same scene set has CPU,
hybrid, GPU, and fallback evidence on the target platforms.
